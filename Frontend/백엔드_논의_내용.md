# 백엔드 담당자와의 채팅 메시지 저장 논의

## 🚨 **핵심 문제: WebSocket 메시지가 서버에 저장되지 않음**

### **문제 상황**
1. **클라이언트에서 메시지 전송**: ✅ 성공
   - WebSocket으로 "hi" 메시지 전송 완료
   - 서버에서 메시지 수신 확인됨

2. **서버 저장**: ❌ **실패**
   - 채팅방 재진입 시 전송한 "hi" 메시지가 사라짐
   - `GET /api/chat/{chatId}/msg` API에서 새로 전송한 메시지가 반환되지 않음

3. **현재 상태**: 
   - WebSocket 메시지는 **메모리에만 저장**되고 **DB에는 저장되지 않는 것 같음**
   - HTTP API로 전송된 메시지만 DB에 저장되는 것으로 보임

## 🎯 **백엔드 담당자에게 전달할 핵심 질문**

### **질문 1: WebSocket 메시지 저장 확인**
> **"WebSocket으로 전송된 메시지가 서버 DB에 실제로 저장되고 있나요?"**

**구체적인 확인 사항:**
- WebSocket 메시지를 받아서 DB에 저장하는 로직이 있는지
- 저장 시 어떤 테이블에 저장되는지
- 저장 실패 시 에러 로그가 있는지

### **질문 2: WebSocket vs HTTP API 저장 방식**
> **"WebSocket과 HTTP API 메시지가 동일한 방식으로 저장되나요?"**

**현재 상황:**
- HTTP API (`POST /api/chat/{chatId}/msg`): 메시지가 DB에 저장됨
- WebSocket (`ws://13.209.75.209:8080/api/ws`): 메시지가 DB에 저장되지 않음

**예상 원인:**
- WebSocket과 HTTP API가 서로 다른 저장 로직을 사용할 가능성
- WebSocket 메시지가 메모리에만 저장되고 DB 저장 로직이 누락된 가능성

## 📊 **기술적 세부사항**

### **WebSocket 메시지 전송 구조**
```
WebSocket 연결: ws://13.209.75.209:8080/api/ws
메시지 전송 Destination: /pub/{chatId}/msg (API 명세서에 따름)
메시지 구독 Topic: /sub/{chatId}/msg (API 명세서에 따름)
Body: {"userId": 10, "message": "hi"}
```

### **HTTP API 메시지 전송 구조**
```
URL: http://13.209.75.209:8080/api/chat/{chatId}/msg
Method: POST
Body: {"userId": 10, "message": "hi"}
```

### **중요한 차이점**
- **WebSocket**: `/pub/{chatId}/msg` (STOMP destination)
- **HTTP API**: `http://13.209.75.209:8080/api/chat/{chatId}/msg` (HTTP URL)

**이 두 URL은 서로 다른 엔드포인트입니다!**

### **현재 클라이언트 로그**
```

2025-08-09 22:01:09.868 AbstractCo...onProvider Send STOMP message: SEND destination:/pub/1/msg {"message":"hi","userId":10}
2025-08-09 22:01:09.870 ChatRoomActivity ✅ WebSocket을 통해 메시지 전송: hi
2025-08-09 22:01:09.882 ChatMessageManager 채팅방 1 새 메시지 추가: hi
2025-08-09 22:01:09.886 WebSocketManager 메시지 전송 성공
```

### **문제 재현 방법**
1. 채팅방 1번에 "hi" 메시지 전송 (WebSocket)
2. 채팅방 나가기
3. 채팅방 1번 재진입
4. **결과**: "hi" 메시지가 사라짐

## 🎯 **핵심 포인트**

### **WebSocket vs HTTP API URL 구조 차이**

**WebSocket (STOMP):**
- 연결: `ws://13.209.75.209:8080/api/ws`
- 메시지 전송: `/pub/{chatId}/msg` (STOMP destination)
- 메시지 구독: `/sub/{chatId}/msg` (STOMP topic)

**HTTP API:**
- URL: `http://13.209.75.209:8080/api/chat/{chatId}/msg`
- Method: POST

### **중요한 차이점**
1. **WebSocket**: STOMP 프로토콜을 사용하여 `/pub/{chatId}/msg` destination으로 메시지 전송
2. **HTTP API**: HTTP 프로토콜을 사용하여 `http://13.209.75.209:8080/api/chat/{chatId}/msg` URL로 요청

**이 두 엔드포인트는 완전히 다른 처리 로직을 가질 수 있습니다!**
